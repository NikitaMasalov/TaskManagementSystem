# TaskManagementSystem

REST API для управления задачами и пользователями на Java 21 и Spring Boot. Задачи можно создавать без исполнителя, назначать пользователям, переназначать, обновлять и удалять. Данные хранятся в MySQL.

API предназначен для администратора системы и защищён HTTP Basic. Веб-интерфейс в проект не входит.

## Возможности

- Полный CRUD для задач и пользователей.
- Фильтрация задач по пользователю.
- Назначение и снятие исполнителя задачи.
- Валидация входных данных и ответы `400`, `404`, `409` для ошибок.
- DTO в ответах: пароли и внутренние JPA-связи не передаются клиенту.
- Хеширование паролей пользователей с помощью PBKDF2 и индивидуальной соли.
- Защита от удаления пользователя, которому назначены задачи.
- Запуск приложения и MySQL через Docker Compose.
- Интеграционные тесты и сборка в GitHub Actions.

## Быстрый запуск через Docker Compose

Потребуются Git, **JDK 21** с компилятором `javac`, Docker с Compose и доступ к Maven Central и Docker Hub. Отдельная установка Maven не нужна. Команды ниже рассчитаны на Bash в Linux, macOS или WSL; для Windows также доступен `mvnw.cmd`.

### 1. Получить проект

```bash
git clone https://github.com/NikitaMasalov/TaskManagementSystem.git
cd TaskManagementSystem
java -version
javac -version
```

Обе версии Java должны быть 21. Если задан `JAVA_HOME`, он должен указывать на полный JDK 21.

### 2. Задать локальные пароли

```bash
cp .env.example .env
```

Откройте `.env` и задайте три разных непустых пароля:

| Переменная | Назначение |
| --- | --- |
| `MYSQL_ROOT_PASSWORD` | Пароль администратора MySQL |
| `MYSQL_PASSWORD` | Пароль пользователя БД `taskapp` |
| `APP_ADMIN_PASSWORD` | Пароль администратора REST API |
| `APP_ADMIN_USERNAME` | Логин администратора API; по умолчанию `admin` |
| `APP_PORT` | Порт приложения на компьютере; по умолчанию `8080` |

`.env` исключён из Git. Docker Compose прочитает его автоматически; само Java-приложение `.env` не загружает. При повторной настройке сохраните существующий файл вместо перезаписи.

### 3. Собрать и запустить

```bash
bash mvnw clean verify
docker compose up --build -d
```

Maven выполнит тесты на H2 и создаст исполняемый JAR. Dockerfile упаковывает этот JAR, поэтому сборку Maven нужно выполнить **до** сборки контейнера. Compose дождётся готовности MySQL и запустит приложение от непривилегированного пользователя.

```bash
docker compose ps
docker compose logs --tail=50 app
curl --fail --silent --show-error -u admin http://127.0.0.1:8080/task
```

`curl` запросит пароль `APP_ADMIN_PASSWORD`. Если вы изменили логин или порт, подставьте свои значения. После старта приложения ожидается HTTP `200` и JSON-массив; для пустой базы — `[]`. Запрос без авторизации возвращает `401`.

Приложение доступно только на loopback-интерфейсе компьютера, MySQL наружу не публикуется. Для доступа по сети потребуется HTTPS через обратный прокси: HTTP Basic не шифрует учётные данные самостоятельно.

### Остановка и обновление

```bash
docker compose stop
docker compose start
```

После изменения кода пересоберите приложение:

```bash
bash mvnw clean verify
docker compose up --build -d
```

`docker compose down` удаляет контейнеры и сеть, сохраняя volume с данными. Параметр `-v` дополнительно удаляет базу. Пароли инициализации MySQL применяются только к пустому volume; изменение `.env` не меняет пароль существующего пользователя БД.

## Запуск Java-приложения без Compose

Подготовьте MySQL 8.4, создайте базу `demo` и пользователя с правами на неё, включая создание и изменение таблиц. Затем задайте переменные в терминале:

```bash
export SPRING_DATASOURCE_URL='jdbc:mysql://127.0.0.1:3306/demo'
export SPRING_DATASOURCE_USERNAME='taskapp'
read -rsp 'Пароль MySQL: ' SPRING_DATASOURCE_PASSWORD
printf '\n'
export SPRING_DATASOURCE_PASSWORD
export SPRING_SECURITY_USER_NAME='admin'
read -rsp 'Пароль администратора API: ' SPRING_SECURITY_USER_PASSWORD
printf '\n'
export SPRING_SECURITY_USER_PASSWORD
export SERVER_ADDRESS='127.0.0.1'
bash mvnw spring-boot:run
```

Для запуска уже собранного JAR с теми же переменными:

```bash
java -jar target/TaskManagementSystem-0.0.1-SNAPSHOT.jar
```

| Переменная | Значение по умолчанию / назначение |
| --- | --- |
| `SPRING_DATASOURCE_URL` | `jdbc:mysql://127.0.0.1:3306/demo` |
| `SPRING_DATASOURCE_USERNAME` | `taskapp` |
| `SPRING_DATASOURCE_PASSWORD` | Задайте пароль своей БД |
| `SPRING_SECURITY_USER_NAME` | `admin` |
| `SPRING_SECURITY_USER_PASSWORD` | Задайте постоянный пароль API; без настройки Spring Boot создаст временный пароль и выведет его при запуске |
| `SERVER_ADDRESS` | Для локального запуска рекомендуется `127.0.0.1` |
| `SERVER_PORT` | `8080` |

База создаётся отдельно, таблицы создаёт и обновляет Hibernate (`ddl-auto=update`). Для остановки Java-процесса нажмите `Ctrl+C`.

## REST API

Все запросы требуют HTTP Basic администратора. Тела запросов и ответов — JSON.

### Задачи

| Метод | Путь | Результат |
| --- | --- | --- |
| `GET` | `/task` | `200`: список всех задач, отсортированный по ID |
| `GET` | `/task?userId=1` | `200`: задачи указанного пользователя; `404`, если пользователя нет |
| `GET` | `/task/{id}` | `200`: одна задача |
| `POST` | `/task` | `201`: созданная задача и заголовок `Location` |
| `PUT` | `/task/{id}` | `200`: полное обновление задачи |
| `POST` | `/task/{id}` | Совместимый с прежней версией вариант обновления |
| `DELETE` | `/task/{id}` | `204`: задача удалена |

Тело создания и обновления:

```json
{
  "title": "Подготовить документацию",
  "description": "Описать запуск и API",
  "status": "NEW",
  "userId": null
}
```

- `title`: непустая строка, до 50 символов.
- `description`: непустая строка, до 255 символов.
- `status`: непустая строка, до 255 символов. Например, `NEW`, `IN_PROGRESS`, `DONE`; фиксированного перечисления нет.
- `userId`: положительный ID существующего пользователя либо `null` для задачи без исполнителя.

При обновлении передавайте все текстовые поля. `userId: null` или отсутствие этого поля снимает исполнителя. Ответ содержит `id`, `title`, `description`, `status`, `userId`.

### Пользователи

| Метод | Путь | Результат |
| --- | --- | --- |
| `GET` | `/user` | `200`: список пользователей, отсортированный по ID |
| `GET` | `/user/{id}` | `200`: один пользователь |
| `POST` | `/user` | `201`: созданный пользователь и заголовок `Location` |
| `PUT` | `/user/{id}` | `200`: полное обновление пользователя |
| `DELETE` | `/user/{id}` | `204`: удаление; `409`, если пользователю назначены задачи |

Тело создания и обновления:

```json
{
  "username": "Алексей",
  "phone": "+79991234567",
  "password": "replace-this-password"
}
```

`username` — непустая строка до 100 символов, `phone` — строка из 7–15 цифр с необязательным `+` в начале, `password` — строка от 8 до 64 символов. Все поля обязательны, в том числе при `PUT`. Телефон хранится строкой, сохраняя ведущие нули.

Ответ содержит только `id`, `username`, `phone`. Пароль сохраняется как хеш PBKDF2 с солью и никогда не включается в ответ. Пользователи `/user` — записи предметной области: их пароли **не дают доступа к API**. Доступ предоставляется отдельной учётной записи администратора из конфигурации.

Перед удалением пользователя переназначьте его задачи, снимите назначение или удалите задачи. Автоматического каскадного удаления задач нет.

### Пример работы

В примере `admin` — логин из конфигурации. Каждая команда `curl -u admin` запросит его пароль. Замените демонстрационный пароль создаваемого пользователя своим.

```bash
# Создать пользователя; сохраните id из ответа.
curl -i -u admin http://127.0.0.1:8080/user \
  -H 'Content-Type: application/json' \
  -d '{"username":"Alex","phone":"+79991234567","password":"replace-this-password"}'

# Создать задачу для пользователя (подставьте его реальный id вместо 1).
curl -i -u admin http://127.0.0.1:8080/task \
  -H 'Content-Type: application/json' \
  -d '{"title":"Документация","description":"Описать API","status":"NEW","userId":1}'

curl -u admin 'http://127.0.0.1:8080/task?userId=1'

# Обновить задачу (подставьте её id вместо 1).
curl -u admin -X PUT http://127.0.0.1:8080/task/1 \
  -H 'Content-Type: application/json' \
  -d '{"title":"Документация","description":"API описан","status":"DONE","userId":1}'

curl -i -u admin -X DELETE http://127.0.0.1:8080/task/1
curl -i -u admin -X DELETE http://127.0.0.1:8080/user/1
```

### Ошибки

| Код | Причина |
| --- | --- |
| `400` | Невалидные поля, некорректный JSON или параметр запроса |
| `401` | Отсутствует или неверна авторизация администратора |
| `404` | Задача или пользователь не найдены |
| `409` | Удаление пользователя с задачами или конфликт ограничений БД |

Ошибки контроллеров возвращаются в формате `ProblemDetail`; ошибки DTO также содержат словарь `errors` с сообщениями по полям. SQL и трассировки стека не передаются в этих ответах.

## Тестирование и CI

```bash
bash mvnw test
bash mvnw clean verify
```

По умолчанию тестовый профиль использует H2 в памяти: Docker и MySQL для этой проверки не нужны. Тесты API выполняются с откатом транзакций. Если в терминале экспортированы `SPRING_DATASOURCE_*`, они переопределяют H2; удалите их из окружения для изолированного запуска.

Проверяются авторизация, CRUD, назначение и переназначение исполнителя, фильтрация, запрет удаления пользователя с задачами, хеширование и отсутствие паролей в ответах, валидация и обработка отсутствующих ресурсов. Отдельный тест проверяет загрузку контекста.

Для проверки на MySQL заранее создайте **отдельную тестовую базу** `demo_test`, выдайте пользователю права на неё и задайте тестовый пароль:

```bash
read -rsp 'Пароль тестовой БД: ' SPRING_DATASOURCE_PASSWORD
printf '\n'
export SPRING_DATASOURCE_PASSWORD
SPRING_DATASOURCE_URL='jdbc:mysql://127.0.0.1:3306/demo_test' \
SPRING_DATASOURCE_USERNAME='taskapp' bash mvnw verify
```

Отчёты находятся в `target/surefire-reports/`. Workflow `.github/workflows/ci.yml` запускает сборку и тесты на H2, собирает Docker-образ и сохраняет JAR и отчёты как артефакты GitHub Actions при push в `main` и pull request.

## Совместимость и границы проекта

- Исправлена ошибка создания задачи без пользователя. Новые ответы задач используют единое поле `userId` вместо старого `user_id` и вложенных сущностей.
- Телефон пользователя теперь строка. Hibernate обновляет прежний числовой столбец; ранее потерянные ведущие нули восстановить автоматически невозможно.
- Новые и обновлённые пароли пользователей хешируются. Для старых записей из прежней версии обновите пароль через `PUT /user/{id}`.
- Это административный API с одной настроенной учётной записью, без самостоятельного входа пользователей, разграничения доступа по владельцу и веб-интерфейса.
- Списки возвращаются целиком, без пагинации. Схемой управляет Hibernate; версионированных миграций пока нет. Перед обновлением существующей базы сохраните резервную копию.

## Решение типичных проблем

| Проблема | Что проверить |
| --- | --- |
| Ошибка компиляции Java 21 | `javac -version`, `bash mvnw -version` и `JAVA_HOME` должны соответствовать JDK 21 |
| Compose требует переменную | Заполните все три пароля в `.env` |
| Не найден JAR при сборке Docker | Сначала выполните `bash mvnw clean verify` |
| `401 Unauthorized` | Укажите логин и пароль API, а не пароль MySQL или пользователя `/user` |
| `Communications link failure` | Проверьте доступность MySQL и JDBC URL; в Compose имя сервера — `db` |
| `Access denied for user` | Проверьте пароль и права БД; старый volume сохраняет прежние учётные данные |
| `Unknown database` | Создайте `demo` или `demo_test` до запуска; Compose создаёт `demo` автоматически |
| Занят порт `8080` | Измените `APP_PORT` в `.env` или `SERVER_PORT` при запуске Java напрямую |
| Maven не работает за прокси | Настройте прокси в Maven `settings.xml`; одного `HTTPS_PROXY` может быть недостаточно |
